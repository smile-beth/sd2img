# sd2img

[English](README.md) | [日本語](README.ja.md)

読み取りエラーや接続切れが起きるSDカードから、物理ディスク全体のイメージを作成するWindows用CLIツールです。進捗をマップに保存し、中断した位置から再開できます。

表示言語はWindowsのユーザーUI言語に従います。日本語環境では日本語、それ以外では英語で表示します。

## 主な機能

- 64 KiBから転送効率に応じて読取サイズを自動調整し、失敗範囲は論理セクタ単位で再走査。
- 順方向・逆方向・ランダムの読取順序。既定はランダム。
- ランダムでは速く読めた領域の未探索側を優先し、成功中は同じ方向へ連続して読みます。候補がなければ未処理範囲全体からランダムに選択。
- 全画面のディスクマップと、読み取り・応答待ち・取消待ち・再接続・リセットの状態表示。
- ボリュームのロックとアンマウントによる、通常のファイルアクセスの抑止。
- Configuration Manager API、SetupAPIの順での自動復旧。
- Ctrl+Cでの保存・終了と、同じ出力先を指定した途中再開。
- 読取成功・エラー・復旧処理の詳細を `<OUTPUT>.log` に追記。

## 動作環境

- Windows。検出・権限昇格・ロックにはWindows APIを直接使い、PowerShellを起動しません。
- ビルドには現在の安定版Rustと、使用するWindowsターゲットに対応するネイティブビルドツールが必要です。
- 物理ディスクを読むための管理者権限。必要に応じてUACで昇格します。
- 元のSDカードとは**別の物理ディスク**に、カード全容量分の空き領域が必要です。
- 全画面表示にはVT対応のWindows端末を使用してください。80列以上を推奨し、最小サイズは45列・20行です。

LinuxとmacOSには対応していません。論理セクタサイズはWindows APIから取得します。512バイト〜64 KiBの2のべき乗サイズに対応し、未対応・不整合な構成は救出前に停止します。

## ビルドと実行

リポジトリのディレクトリで実行します。

```powershell
cargo build --release --locked
.\target\release\sd2img.exe --help
```

Windowsの「ディスクの管理」、または次の任意のPowerShellコマンドで元ディスクを確認してください。このコマンドは確認用で、ツールの動作には使いません。

```powershell
Get-Disk | Format-Table Number, FriendlyName, BusType, Size, IsBoot, IsSystem
```

物理ディスク2を別ディスク上のイメージに保存する例です。ディスク番号と出力先は自分の環境に置き換え、出力ディレクトリを先に作成してください。

```powershell
.\target\release\sd2img.exe -d 2 "D:\Recovery\card.img"
```

ドライブレターも指定できます。レターは物理ディスクの特定にだけ使い、そのパーティションだけでなく、**所属するディスク全体**を読み取ります。

```powershell
.\target\release\sd2img.exe -d E: "D:\Recovery\card.img"
```

`-d` を省略すると自動選択します。SD/MMC/USB接続のディスクを候補にし、Windowsのシステムディスク、EFIシステムパーティションやアクティブMBRブートパーティションのあるディスク、構成を確認できないディスクを除外します。候補が0台または複数台の場合は選択せず停止します。

明示的に指定したディスクには、この自動選択フィルターは適用しません。ロック処理は常に行います。元ディスクは必ず自分でも確認してください。

## 引数

| `-d`, `--drive` | `auto` | 物理ディスク番号、ドライブレター、または `auto`。 |

| `--operation-timeout` | `10` | 操作遅延・リセットの観測時間と、実績がない正常確認の待ち時間（秒）。0より大きく3600以下。 |

| `-h`, `--help` | | ヘルプ。 |
| `-V`, `--version` | | バージョン。 |

```powershell
.\target\release\sd2img.exe -d E: --direction reverse --timeout 1.5 "D:\Recovery\card.img"
```

## 全画面表示とログ

全画面表示が既定です。

- **上部：固定高さ。** 元ディスク・出力先・容量・各状態のセクタ数・現在の処理・状態・OK/NG別の応答時間と、通常成功／待機後成功の転送速度を平均・中央値付きで表示します。
- **中央：可変高さ。** 端末サイズから1マスのセクタ数を自動計算し、末尾を含むディスク全体を表示します。画面サイズ変更にも追従します。
- **下部：固定5行。** 注意事項・リセット試行・エラーを表示します。長いメッセージはこの領域内で折り返します。

| マップ | 意味 |
| --- | --- |
| 灰色 `.` | マス全体が未処理。 |
| 緑 `#` | マス全体が読取・イメージ書込済み。 |
| 赤 `x` | 一部に読取失敗・再走査待ち・再試行待ち・NGを含む。 |
| 明るい赤 `X` | マス全体が読取失敗・再走査待ち・再試行待ち・NG。救出済みと未処理は含まない。回復不能の確定ではありません。 |
| 青 `:` | 1マスに救出済みと未処理が混在。 |
| 水色 `R` | 現在読み取り中の範囲。 |
| 黄 `W` | タイムアウト後も完了を待っている範囲。 |

現在処理中の表示を最優先にします。`#` は全範囲が救出済み、`X` は全範囲がNG・再試行待ちです。`x` と `:` は状態の混在を表します。

現在の読み取りは表示中のタイムアウトまでは `R`（読み取り中）、タイムアウト以上で未完了なら `W`（応答待ち）です。同じマスに過去の待機要求があっても、現在の `R` を優先します。描画専用スレッドはストレージにアクセスせず、読み取り処理が待っている間もアニメーションを更新します。

ビルド識別子・起動設定、要求IDと用途、タイムアウトと所要時間、読取成功、探索先の選択理由、エラー、リセットの試行・結果は、ローカル時刻付きで `<OUTPUT>.log` に**追記**します。たとえば `card.img` のログは `card.img.log` です。再開時も既存ログを消しません。色コードは記録しません。

セクタ数には `128 セクタ / 64.00 KiB (65536 バイト)` のように、単位付きサイズと正確なバイト数を併記します。マップ保存は画面更新とは独立して行います。`NO_COLOR` 環境変数で色を無効にでき、標準出力をリダイレクトした場合は全画面描画を行わず詳細ログを記録します。

## 論理セクタサイズと読取サイズの自動調整

並列数は `--max-parallel-reads 16` のように指定できます（既定16、1〜64）。これはOSスレッド数ではなく、走査の未完了I/O要求の上限です。タイムアウト後は正常確認を挟まず次の領域へ進み、上限に達したら正常確認用の別枠1件でリセットの要否を判断します。既定では走査16件＋正常確認1件、合計最大17件です。

読取サイズとタイムアウトは論理的な連続読み取りの流れごとに保持します。タイムアウトした流れはそこで終了し、未完了のI/O要求だけを保持します。遅れて成功した場合は、そのデータをイメージへ保存して救出済みに更新しますが、元の連続領域の続きを優先的に読み始めることはありません。現在進んでいる読み取りはそのまま継続します。通常時と未完了要求がある時も学習を分けます。学習状態はプロセス内に保持し、再起動時には再測定します。

CM・SetupAPIはそれぞれ失敗時に10、20、40、80、160、300秒（以降最大300秒）の再試行待ちを設けます。その間も基準セクタと再接続を確認し、待ち時間だけを理由に元ハンドルを閉じません。

ログにはビルド識別子と全起動設定、I/O要求ID、用途（走査・初期探索・正常確認・再開確認・復旧確認）、要求サイズ、適用タイムアウト、所要時間、未完了件数、読み取りの流れのID、基準LBAの更新、復旧前回以降の救出量を記録します。遅延完了の所要時間は完了を観測した時点までの時間です。

Windowsの `StorageAccessAlignmentProperty` から論理セクタサイズを取得し、未対応の場合はディスク構成APIへフォールバックします。開いたデバイスごとに保持し、再接続時に再確認するため、読み取りのたびに問い合わせません。

新しいマップには `SECTOR_SIZE <バイト数>` を記録します。この記載がない既存マップは必ず**512バイト単位**として読み込み、内容から推測しません。マップとAPIの値が異なる場合は、LBAを再解釈せず停止します。基準セクタ、オフセット、容量表示、復旧処理も同じ単位を使います。

大ブロック走査は**64 KiB**から開始します。正常に読めた要求について、ログ出力・イメージ書込時間を除くI/O時間をバイト数で割り、7回分の中央値で効率を比較します。5%を超えて改善する間は要求を倍増し、改善しなければ小さい方のサイズを、その連続領域で維持します。読取タイムアウトは、直近の正常な走査読み取りの所要時間 × 次の要求バイト数 ÷ 成功した要求バイト数で計算し、`--timeout` を下限としてミリ秒単位で切り上げます。64 KiBが1秒なら128 KiBは2秒、256 KiBは4秒です。成功実績がない場合は初期値を使い、失敗した読み取りは計算に使いません。

エラーまたは非連続の領域への移動で64 KiBから再測定します。領域末尾などで短くなった要求は、完全なサイズの測定サンプルには数えません。細かい再走査は、引き続き1論理セクタ単位です。バッファーは必要時だけ拡大し、エラー後・小さいサイズへの確定時・細かい走査への移行時には縮小します。

既定の**1 GiBは設定上の上限**です。最初から1 GiBを確保・読み取りするわけではなく、必ずそこまで拡大するわけでもありません。上限を抑える場合は次のように指定します。

```powershell
.\target\release\sd2img.exe -d E: --max-read-size 4MiB "D:\Recovery\card.img"
```

整数と、bytes・`KiB`・`MiB`・`GiB`、または10進の `KB`・`MB`・`GB` を受け付けます。指定範囲は64 KiB〜4,294,967,295バイトで、端数は論理セクタ単位で切り下げます。`4MB` と `4MiB` は異なる上限です。

## 応答時間と長時間待機の扱い

応答時間は**平均／中央値**を小数3桁で、OK／NG別に表示します。起動後に完了した全件を対象とし、正常確認などの元ディスク読み取りも含めます。未完了の要求はNGに数えず、Ctrl+Cによる中断は除外します。遅延完了の時間は完了を観測した時点までのため、次の確認までの待ち時間を含む場合があります。

転送速度は1行で、**通常成功／待機後成功**それぞれの平均／中央値を表示します。平均は成功バイト数合計÷要求所要時間合計、中央値は各成功要求の「バイト数÷所要時間」の中央値です。MB/s・KB/s・B/sを10進単位で自動選択します。失敗要求と正常確認・復旧確認は速度に含めません。並列要求の時間は重なるため、壁時計時間あたりの救出量とは異なります。通常成功は待機要求として退避されずに成功したもの、待機後成功は退避した要求が遅れて成功したものです。いずれも直近件数による制限はなく、再起動で集計をリセットします。中央値は逐次更新し、画面描画ごとに全履歴をコピー・並べ替えません。

- `--timeout 2` は、別領域へ進むまでの時間の初期値・下限です。各読み取りの流れで、成功した要求の時間とサイズから自動調整し、通常時と未完了要求がある時の学習を分けます。新しい流れは初期値から始めます。タイムアウトしても元の読み取りはキャンセルせず、専用ハンドル・イベント・バッファーを保持します。遅れて成功した結果は保存しますが、その続きの走査や前後候補の追加はしません。
- 走査の待機上限または未完了バッファーの上限に達したら、直近最大**30個の異なる成功候補**から最速のものを正常確認に使います。候補はメモリー内のみで保持し、画面のマップやマップファイルには一覧を出しません。走査の全要求時間を暫定実績とし、1セクタの確認が成功したらその実測値で更新します。待ち時間は選んだ候補の直近実績**＋2秒**です。実績がない場合、正常確認・復旧確認は `--operation-timeout` と `--timeout` の大きい方、起動時の再開確認は `--operation-timeout` を使います。確認中の要求は重複発行せず、同じ要求の時間予算を繰り返し延長しません。再試行待ちしか残っていない場合も正常確認して再接続を判断します。
- `--max-parallel-reads` は**走査**の未完了要求上限です（既定**16件**、1〜64件）。正常確認は別枠で最大1件なので、既定で合計最大17件、最大設定で65件です。走査のタイムアウトごとに次を1件ずつ追加し、一括で上限まで発行しません。上限到達時は新たな走査を止め、正常確認して復旧を判断します。正常確認に成功しても、走査枠が空くまでは走査要求を増やしません。
- 未完了I/Oバッファーの合計上限は**2 GiB**で、走査側はその中の64 KiBを正常確認用に空けます。設定上の読取上限が大きくても、実際の1要求は2 GiB未満に制限します。正常確認は1論理セクタです。
- 正常確認が失敗・期限超過したら復旧を試みます。`--operation-timeout` は遅いネイティブ操作の通知・リセットの観測時間にも使いますが、未完了の読み取りやリセットを強制終了しません。リセット子プロセスは1つだけ保持し、重ねて発行しません。復旧確認と再接続を継続し、対象・容量・セクタサイズ・基準データ・ボリューム保護を確認できれば走査を再開します。
- Windowsの呼び出しが戻らず、呼び出し元だけが待たされる場合があります。描画は継続します。未完了は永久的な不良を意味しません。大ブロックの失敗も、その中のどのセクタが原因か、全セクタがNGなのかを確定するものではありません。

## Ctrl+C・カードの抜き差し・安全な再開

**実行中のCtrl+CまたはCtrl+Breakによる中断に対応しています。** 現在の読み取りにキャンセルを要求し、Windowsがまだ参照しているI/O用のメモリーやハンドルは完了通知またはプロセス終了まで保持します。そのうえでイメージのデータを書き出し、マップを保存して終了します。イメージ書込は1 MiBずつに分割し、大きな読み取りの全データを書き終える前でも、書込済みセクタを保存して停止できます。通常終了を待ってから、同じカード・同じ出力先で再実行すれば、救出済みのセクタを飛ばして安全に続行できます。Enter入力は不要です。

**読み取り中に同じSDカードを抜き差しした場合も、再接続後の続行に対応しています。** 通常のタイムアウト直後は別領域へ進み、即座に再接続待ちへは入りません。復旧が必要な段階で新しい走査を止め、最低1秒間隔で再接続を確認します。容量・セクタサイズ・基準データが一致し、ボリュームを保護できたことを確認してから再開します。未読範囲を救出済みとは扱いません。再接続のためのEnter入力は不要です。

イメージの書き出しを完了してから対応するマップを保存します。マップに救出済み範囲があるのにイメージがない、イメージのサイズが違う、マップの範囲に欠落・重複・容量不一致がある場合は、そのまま再開せず停止します。対応するマップがない既存の非空イメージも上書きしません。

`card.img` と `card.img.map` は必ず対で保管してください。マップだけ残してイメージを削除した場合、救出済みデータは再構成できません。

開始前に読み取り専用の物理ディスクハンドルを開き、その後に元ディスク上の全ボリュームをロック・アンマウントして、通常のファイルアクセスや再マウントを抑止します。ロック成功前に元データを読み取ることはありません。構成・容量照会用ハンドルにも `GENERIC_READ` を指定します。管理者であっても、容量照会APIに必要なハンドル権限を省略することはできません。レターのないボリュームも対象です。開始時に他アプリが使用中などでロックできない場合は、強制アンマウントせず読み取りを止め、エラー表示を保持します。再接続時のロック失敗はログに記録して再試行し、未保護の状態では走査しません。ロックは走査中保持し、再接続確認も既存ハンドルが使える場合はそのまま行います。新規ハンドルが必要な再接続やデバイスリセット時は一時解放し、新規オープン後・読み取り前に取り直します。レターの割り当ては削除しません。走査の後処理でハンドルを閉じてロックを解放します。最終確認画面を表示している間は元ディスクのロックを保持せず、その後Windowsから再度マウントできます。

容量と基準セクタは整合性確認であり、カード固有の識別を保証しません。必ず**同じカード**を戻してください。抜き差しでディスク番号が変わる場合があるため、番号指定で再実行する際は確認してください。

これらはプログラムと保存データの整合性を保つための機能です。故障したカード・リーダー・ドライバーの復旧や、物理的な損傷が起きないことまでは保証できません。ドライバーによってはI/O取消やプロセス終了に時間がかかります。強制終了、端末を閉じる操作、電源断は、通常のCtrl+C終了と同等ではありません。起動直後の検証に失敗して停止した場合も、対象とファイルを確認して同じコマンドで再実行してください。

**処理完了やエラー時は、明示操作まで表示を保持します。** 標準入力が端末ならEnterで終了し、標準入力が端末でない場合は明示的な停止要求までプロセスを保持します。これは復旧の自動再試行とは別です。Ctrl+C／Ctrl+Breakで中断した場合は、後処理後にEnterを待たず終了します。ヘルプ・バージョン表示や引数解析エラーはCLI側で処理し、この最終確認画面の対象ではありません。

## 自動復旧

走査の待機上限に達して正常確認が成立しない場合、または再試行待ちセクタだけが残って正常確認が成立しない場合、保存後に元ディスクのハンドルとロックを閉じ、次の順で復旧を試します。

1. **Configuration Manager API**で、対象ディスクのデバイスインスタンスを取り外し・再起動・再列挙します。永続的な無効化は行わず、USBコントローラーや兄弟ディスク自体をリセットしません。
2. 完了通知を受けたうえで失敗・応答検証失敗なら、**SetupAPI**の `DIF_PROPERTYCHANGE` で同じディスクの有効化・再起動を試します。
3. 両方で復旧しない場合に、「同じカードを抜き差しすると改善する場合があります」と表示し、自動再試行を続けます。

試行と結果は画面下部と `.log` の両方に出ます。APIが成功しても、容量と基準セクタが一致しなければ復旧成功にはしません。自動リセットの重複発行を防ぎ、失敗した方法は待ち時間を置いて再試行します。

PnP操作は非表示のsd2img子プロセス1つで実行します。子プロセスは元データを読み取らず、すべての読み取りを走査側が管理し、走査上限とは別に正常確認用の1枠を設けます。観測時間を超えても子プロセスを終了させず、完了通知を確認し続けます。完了前に別のリセットを発行しません。API完了と、容量・基準セクタを検証した走査再開は区別して記録します。通常の探索や走査でPowerShellは起動しません。対象インスタンスを特定できない場合は、他の機器をリセットしません。Ctrl+C時はイメージとマップを保存したうえで、未完了リセットの完了通知を待つ場合があります。

## ランダム走査と正常領域の前後の優先

タイムアウト前に成功した連続領域の前後を、未探索側の候補としてメモリー内に保持します。成功中はその方向へ連続して読み、待ち・失敗になった側の候補は破棄します。新しい探索先を選ぶ時には、処理済みや再試行待ちの候補を除外し、残った候補からランダムに選びます。候補がなければ、管理領域による重み付けをせず未処理範囲全体からランダムに選びます。

例えば100〜131が成功し132で待ちになった場合、100の手前の84〜99を優先します。そこが成功すれば68〜83へと小さいLBA方向へ進みます。遅れて成功した要求はデータの保存だけで終了し、前後の優先候補には追加しません。明示的な `forward` / `reverse` の順序は変更しません。

候補は最大1,024件で、上限を超えた古い候補は削除します。マップファイルの形式や保存項目は増やさず、再起動時には候補をリセットします。ログの `[scan target]` に選択理由（`fast-neighbor` / `random`）と方向を記録します。

## マップ形式

イメージは元ディスク全容量で確保します。新規イメージの未読部分は初期状態でゼロですが、正常に取得したかどうかはファイルサイズでは判断せず、マップの `+` を確認してください。

独自のテキスト形式であり、GNU ddrescueのマップとは互換性がありません。

- セクタサイズ行：`SECTOR_SIZE <論理セクタのバイト数>`。記載がなければ512バイト単位として読み込みます。
- 基準行：`GOOD <基準LBA> <1論理セクタ分の16進表記>`。
  正常な読み取りをイメージへ書き込むたび、その範囲の末尾1セクタを最新の基準に更新します。遅れて成功した読み取りも対象です。この保存用1件は、実行中の最大30件の時間付き候補とは別です。約3秒経過後に走査ループへ制御が戻った時、復旧前、終了時のチェックポイントで保存するため、I/Oが止まっている間は定期保存が遅れる場合があります。
- 以降：`<開始LBA> <セクタ数> <状態>`。

| 状態 | 内容 |
| --- | --- |
| `?` | 未処理。 |
| `+` | 読取・イメージ書込済み。 |
| `~` | 大ブロックで失敗または応答待ちになり、セクタ単位の走査待ち。 |
| `*` | セクタ単位の失敗や未完了要求との重複による再試行待ち。 |
| `-` | NGとして記録された範囲。`--retry-bad` で再走査。 |

救出済み（`+`）は後の確認失敗や再試行で未処理・NGへ戻しません。正常確認の遅延完了は保存データとの一致と候補の時間を確認し、救出済みイメージへ再書き込みしません。失敗した要求は `~` または `*` と記録し、細かい再走査・再試行の対象にします。

## 制限とデータの扱い

- 元ディスクは読み取り専用で開きます。ただし、Windowsはボリュームロック前にキャッシュを書き出すため、準備操作を含めた完全な書き込みゼロは保証しません。他の管理者ツールによる物理ディスクへの直接アクセスも完全には防ぎません。
- イメージ・マップ・一時マップ・ログが元ディスク上にないことを確認してからロックします。出力先は元カードとは別の物理ディスクにしてください。
- 新規開始には先頭10,000セクタ以内に読み取り可能な基準セクタが必要です。再開にもその基準セクタが読める必要があります。
- リセットは電源の入れ直しを保証するものではなく、物理的な抜き差しが必要な場合があります。
- ファイルシステムの修復やファイル単位の取り出しは行いません。RAWイメージを作成するツールです。
- イメージには削除済みデータ、マップには実データ1セクタ、ログにはパスや復旧情報が含まれ得ます。これらをIssueやPRに添付しないでください。

## 開発

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
```

テストには合成データ、一時ファイル、名前付きパイプを使い、実カードにはアクセスしません。Windowsの実際の未完了読み取りの中断、探索開始時間を超えた要求のメモリー保持、遅れて成功した結果の回収、並列数上限、読取先の切断、512バイト／4096バイトのマップと読み取り、保存・再開、効率に応じたサイズ調整、スケジューリング、リセットの切替順序、OK/NG別の待ち時間、ログ追記、言語選択、端末サイズ変更を検証します。操作監視の登録・解除も検証します。テストコードは各ソースファイル内の `#[cfg(test)] mod tests` にあり、通常の実行ファイルには含まれません。実機のリセット挙動はリーダーやドライバーに依存します。

### GitHub Releasesへの公開

[リリースワークフロー](.github/workflows/release.yml)は、`v1.2.3`のような安定版の `vMAJOR.MINOR.PATCH` タグのpushで動作します。タグのコミットが `main` に含まれることをビルド前に検証します。先にワークフローとスクリプトを `main` へ反映してください。

```powershell
git switch main
git pull --ff-only
git tag v1.2.3
git push origin main
git push origin v1.2.3
```

タグの値を実行ファイルのバージョンに使います。ビルド用の `Cargo.toml` と `Cargo.lock` のsd2img項目へ反映し、リリース用スクリプトのテスト、Rustの整形・Clippy・テスト、Windows x64のビルド、`--version` の照合を行います。バージョンの書き換えはビルド環境内だけで、push済みタグやソースブランチは変更しません。Cランタイムは静的リンクし、exe単体で配布できます。ビルドでは救出用のイメージ・マップ・ログは作成しません。

公開するのは `sd2img-v1.2.3-windows-x86_64.exe` と、任意で照合に使える `.sha256` ファイルです。実行にはexeだけで足ります。下書きReleaseへ添付を完了してから公開します。`gh release create --generate-notes` により、手動の「Generate release notes」と同じ[GitHubの自動生成機能](https://docs.github.com/en/repositories/releasing-projects-on-github/automatically-generated-release-notes)で、マージされたPR、貢献者、変更履歴リンクを含む概要を作成します。再実行時は公開済みReleaseを維持し、未完了の下書きは同じタグで再試行できます。

認証には `contents: write` 権限の `GITHUB_TOKEN` を使います。リポジトリでActionsを有効にし、組織・リポジトリの権限ポリシーとタグルールで許可してください。通常は追加の個人アクセストークンは不要です。公開処理は1件ずつ実行し、最大100件の待機実行をキューに保持します。リリース用スクリプトはPython 3.11以上に対応し、CIではPython 3.14を使います。ローカルの確認コマンドは次のとおりです。

```powershell
python -m unittest discover -s .github/scripts -p "test_*.py" -v
```

`main.rs` は起動処理に限定し、CLI、割り込み、ディスクI/O、セクタサイズ、読取サイズ調整、マップ、イメージ保存、走査、正常領域の前後の選択、読み取りの流れごとの学習、正常確認、画面、ログ、ボリューム管理、リセット、待機監視を目的別のモジュールに分割しています。`build.rs` はログ識別用のビルド時刻IDを埋め込みます。Windows CIは整形・Clippy・合成データのテスト・ロック付きリリースビルドを実行します。詳細は英語版READMEのSource layoutを参照してください。
